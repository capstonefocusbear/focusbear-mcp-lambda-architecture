# Auth0 MCP v2 Implementation Plan

> **For agentic workers:** Use executing-plans and test-driven-development. Independent protocol, backend and infrastructure work uses dispatching-parallel-agents; all changes are integrated and reviewed before completion.

**Goal:** Implement the remaining repository-owned requirements in the approved Group 76 v2 design.
**Architecture:** Auth0 issues one MCP-audience access token. The stateless adapter and dedicated backend routes validate it independently. Backend owns durable agent connections and assignments; legacy authentication remains separate. Local AWS integration uses a shared container and CDK definition.
**Tech stack:** Node 22, TypeScript, NestJS, PostgreSQL, Redis, jsonwebtoken/jwks-rsa, MCP SDK and a tested 2026 transport adapter, Docker, CDK/LocalStack.
**Spec:** /Users/krish/Downloads/Group76_New_Architectural_Design_Auth0_LocalStack_v2.pdf (approved by user's instruction to implement).

## Global constraints

- No PR approval/merge, production deployment or changes to real Auth0 settings.
- One canonical /mcp resource audience, approved clients only, Auth0 token profile default (azp); optional explicit RFC9068 profile (client_id).
- Lambda has no OAuth keys, token exchange, database access or user/agent overrides.
- Preserve legacy tokens/names/assignments with additive migration and controlled linking.
- LocalStack only for local AWS; production owned by Focus Bear in unavailable aws-infra repository. Prepare portable integration source, mark it unverified there.
- MCP 2026-07-28 requires metadata headers/body agreement and no initialize/session dependency; demonstrate adapter compatibility rather than claiming SDK native support.
- Concurrency 10; 30-day logs; bounded requests/retries; per-user shared backend limit.
- Context7 tools unavailable. Read installed library sources and official documentation instead.

## Review focus

- Invalid JWT must never fall back to opaque-token verification.
- Disabled connection and cross-user task assignment must fail closed.
- Concurrent first calls must resolve one durable identity.
- HTTP gateway Host/path forwarding and Docker backend addressing must work without disabling production URL checks.
- Local deploy commands must not target real AWS; absent external configuration must be reported, not substituted.
